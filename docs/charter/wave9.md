## 〇、这一波的主线：控制台上的「假事实」

八波下来，判定链路本身已经相当扎实，而这一波扫出来的缺陷高度集中在**同一个形态**：

> 控制台把「不知道」「建号那天的值」「写死的常量」渲染成**当下的事实**，
> 且与同一套控制台的另一页互相矛盾。

它比"功能没做"更危险——功能没做时管理员会去找入口，而假事实会让他停止寻找。
本波 11 条行动里有 7 条属于这一族：

| 页面显示 | 实际是什么 | 同一套控制台里与谁矛盾 |
|---|---|---|
| 顶栏「安全管理员 / security-admin」 | 两句写死的中文 | 该账号真实角色是**超管**；换审计管理员登录也一字不改 |
| 用户与角色「在线 / Windows 11 / 10.8.2.31 / 无风险」 | 建号那一刻的 INSERT 值，全仓无 UPDATE | 「在线用户」页读的是网关真实会话，两个数并排显示 |
| 用户状态页的「在线」绿点 | posture 上报在 10 分钟内 = **采集器还活着** | 同上，且这一页的定位恰恰是"要不要现在踢他" |
| 审计中心 18.4 万条流水 | 一整块 MOCK；`/audit` 403 时原样保留 | 标签写「降级演示」，而真实原因是**没有审计权限** |
| 隐身页「攻击面 = 0 · 无任何端口可探测」 | 只看内核态隐身回执 | 七层 Web 代理口**不受 SPA 隐身保护**（端口表逐字写着） |
| 系统管理页「已注册 passkey」 | 对 `twoFa=true` 一律这么写 | 只绑了 TOTP 的管理员被显示成绑了 passkey |
| 用户「认证方式：SAML SSO / 密码+UKey」 | 一列零消费方的自由文本 | 白帝**一种都没实现**；管理员那张表早就改成实算了 |

## 一、行动清单

### A. 身份与权限（控制台此前对三权分立完全不可见）

**1. `GET /auth/me` 下发现算的管理员角色与权限键 — S ✅**
- 后端：`handleMe` 补 `displayName` + `adminRole{key,name,power,perms,scope,builtin}`，
  角色走 `currentAdminRoleQuiet`（与 `requirePerm` 同一个取数口，**现算不读令牌**——
  降权后旧令牌下一次拉身份就要看到新角色）。
- **只有完整会话令牌才下发**（`c.Use == ""`）：`/auth/me` 在 `auth.pwResetAllowed` 里对
  受限改密令牌是放行的，那是一个连自己口令都还没换的半程态。
- 前端 `lib/me.ts`：`permKnown` 区分「判不出来」与「确定无权」；`can()` 判不出来时
  **fail-open**（真闸在后端，少显示一个按钮却没有任何报错才是更坏的错法）。
- 测试 `me_identity_test.go` 四向 + 2 变异（去掉 use 闸 / 角色冻住）。

**2. 管理台补二次认证注册入口（FR-ADMIN-16/17）— S ✅**
  系统管理页专列一栏「二次认证」并持续显示「未注册」，而管理员在整个管理台里
  找不到任何地方去注册——注册页 `/portal/security` 一直存在，只是没有一个链接到得了。
  账户菜单补一项。同批把那一栏从写死的「已注册 passkey」改成读后端新增的
  **机读因子清单** `AdminAccount.Factors`（中文摘要 `Auth` 由它派生，照 `AdminRole`
  的 `Perms`/`Scope` 分工）。

**3. passkey 的 helpdesk 通道（FR-ADMIN-17/20）— S ✅ ★本波最严重的一条**
  三条各自正确的规则合起来把账号锁死：passkey 没有恢复码 · `DeleteWebauthnCredential`
  拒绝删最后一个（那道守卫的前提是**本人还能登录**）· `secondFactor` 规定
  「已注册 passkey 即无条件强制断言，策略豁免碰不到」。
  于是认证器一丢 = **永久登不进来**，本人删不掉、管理员侧连一个端点都没有，
  唯一出路是运维直接删库——而 TOTP 那边（`handleAdminResetTotp`）的注释早就把
  这条路判过死刑。新增 `DELETE /users/{id}/passkeys`，与 TOTP 那条逐字对称
  （`PermSecurity` + `guardAdminTarget`）。3 变异。

**4. 防爆破配置的权限发错了人（FR-POLICY-06/07）— S ✅**
  `PUT /security/lockout-config` 挂在 `PermSystem` 上，而同一文件里的**解锁**、
  同一页面上的接入策略、权限键自己的中文定义三处都指向 `security`。失衡是双向的：
  安全管理员能解锁被锁账号却调不动阈值；**系统管理员能把 ipEnabled/accountEnabled
  双双关掉，静默关闭全站登录防爆破**。改成 `PermSecurity`，进 RBAC 矩阵测试。

### B. 判定与记账（会当场做出错误的安全判断）

**5. 多认证域下本地口令爆破既不计锁定也不落审计（FR-AUTH-09 + FR-MON-14/17）— S ✅**
  `routeDirectory` 在「外部源 ≥2 且未指定 directory」时回 ambiguous，门户登录这条
  分支**直接 return**——不计数、不审计。豁免的本意是放过"合法外部用户忘了选域"，
  但它对**本地口令账号**同样生效：
  > 部署一旦接了两个外部源（PRD FR-USER-01 正要求多目录并存），对 `/portal/login`
  > 反复提交 `{username: admin, password: 猜的}` 且不带 directory，每次都从那里 return；
  > 而口令一旦**猜对**，代码根本不进这个 if 块，直接登录成功。
  > 响应差异构成一个干净的口令预言机，整段爆破在两张表与审计中心里恒不可见。

  收口后的**不变式**：一次输错的本地口令算不算数，**不该随部署接了几个认证源而改变**
  （判据 `found && cred.PassHash != ""`，外部绑定账号 pass_hash 恒空，精确保住原豁免）。
  3 变异，含"过度收口"那一向。

**6. 资源 backend 只校验端口不校验主机形态（FR-TUN-02，P0）— S ✅**
  `net.SplitHostPort` 对主机部分什么都不检查，于是**实测**这些全都 200 OK 落库：
  `10.0.0.0/24:443`（网段）· `10.1.1.1-10.1.1.99:80`（地址范围）· `*.corp.internal:443`（泛域名）。
  而对象库把这三种形态都当**一等对象**提供并做成种子，资源编辑器还会拿选中的对象
  自动回填 backend——照着页面给的选项点两下就能存出一条网关永远拨不出去的资源。
  拒绝要**说得出正确形态**（同 IPSec peer 拒收 FQDN 那条的教训）：泛域名那条要点名
  「白帝不做泛域名代理」，否则管理员只会换个写法再试。4 变异（含"一律拒"那一向）。

**7. 闲置账号治理只做了一半（FR-MON-19，SCOPE 已标 wave9）— M ✅**
  阈值只从 URL 参数取（刷新一次就回到写死的 90 天）、`autoLockEnabled` 整项不存在，
  于是 PRD 验收那句「若开启自动锁定，Then 该账号被自动锁定」**没有任何执行方**。
  新增 `store.IdlePolicy`（落 settings，出厂 90 天 + **不自动锁定**）+
  `GET/PUT /users/idle/policy` + `StartIdleLockLoop`。三条纪律：
  自动锁定与手工批量**共用 `lockIdleAccount` 一条路径**（含防自锁、管理员目标闸、
  数据面撤窗）· **永不处置管理员账号**（那条路径上没有调用方可比对 `PermAdmins`）·
  管理员跳过**不逐条记审计**（每小时一轮，一个长期不登录的审计管理员就够把审计冲成噪声）。
  5 变异。前端把「编辑草稿」与「已落库」分开存——只有一份的话，输入框里刚敲下的数字
  会被页面说成"落库的策略阈值是 N，自动锁定按后者执行"。

### C. 假事实（见上表）

**8. 用户目录四列脱冻结值（FR-USER-03/FR-MON-04）— S ✅**
  `online/risk/device/ip` 全仓无 UPDATE（`grep -E "UPDATE users SET (online|risk|device|ip)"` 零命中）。
  改为按真实信号现算：会话（与 `/online` 同源）· posture 最新上报 · `riskOfAccount`
  （与在线会话页同一处判定）。取不到一律降级成 `—` / `unknown`，
  **绝不保留库里那个陈年好值**——从未上报过环境的账号显示「无风险」是替一台完全
  未知的机器背书。前端同批把 `unknown` 单列成灰色「不可判定」（原兜底是绿色「正常」）。

**9. 「在线」在控制台上只能有一个判据（FR-MON-14/10）— S ✅**
  用户状态页读的是 `hasRep && now-rep.TS <= 600`——那是**采集器还活着**，
  不是"此刻连着隧道"。统一到 `onlineAccounts()`。
  ★这条的变异第一次是**逃逸的**：测试服务器里既没有会话也没有 posture 上报，
  两套判据都算出"不在线"。补上"刚上报过 posture 但没有会话"这个唯一能区分的状态后才真的钉住。

**10. 审计中心不再编造记录 / 大屏不再真假同屏 — S ✅**
  审计页 MOCK 整块删除（18.4 万条访问决策 + 十条署名到人的流水）：`/audit` 归 `PermAudit`，
  安全/系统管理员打开这一页拿到的是 403，而页面把**权限拒绝**说成"后端没起"
  并配一屏看起来完全正常的审计。大屏改成「只要有任何一路拿到真数据，
  就绝不让另一路的演示数据同屏」，并把缺了哪一路点名写在屏上（大屏没人会去 hover）。

**11. 隐身页的「攻击面 = 0」把 L7 敞口算进去（FR-SEC-SPA-02/05/12）— S ✅**
  控制面一直收得到网关上报的 `web` 监听地址，只是没人读。`GatewayBundle` 补
  `webExposed`/`webEndpoints`，`allArmed` 加第二个前提，并出一条说清
  「B/S 免客户端接入与端口隐身是一组取舍，不能同时成立」的告警。3 变异。

### D. 交互与可用性（控制台审计那一轮的产物）

- **后端拒绝原因被吞掉**：全仓 ~35 处 `} catch { Message.error('请检查权限或后端连接') }`
  —— 后端的「最后一名超级管理员不可禁用」「角色「审计管理员」无权执行该操作（需要权限：security）」
  被整句丢掉换成一个**猜的归因**。`api.ts` 自己在 `errText` 上方写下过这条纪律，
  而每一个调用点都没照做。收口到 `failReason(e)`，并给 `check-dead-ui.mjs` 加**规则三**守着。
- **十几处 `msg.startsWith('403')` 是死分支**：`api()` 抛的是后端中文原文，永远不以状态码开头。
  改成 `failStatus(e)`（状态码现在挂在 `ApiError` 上）。
- **顶栏三件套**：写死的身份 → 真实身份；写死的红点 `6` → 真实待处理告警（可点开）；
  装饰性的 `<div>` 搜索框 → 真全局搜索（⌘K，页面/用户/应用/资源/网关五类，
  取数失败**点名说清缺了哪一类**——静默少搜一类比没有搜索更坏）。
- **不可逆操作补二次确认**：删资源（并把后端专门算好的**连带影响回执**呈现出来，
  此前应答体连接都没接）· 删安全基线 · 撤销 JIT 授予（理由改由管理员填，
  不再写死成一句对每条授予都一样的话）· 重置 TOTP / passkey。
- **审计中心**：类别字典收敛到 `store.AuditCategories` 一处（`policy` 此前
  **写得进库、任何一张卡都数不到、按它筛直接 400**）· 补源 IP 检索维度 ·
  时间快选的 `toISOString()` 时区错位（UTC+8 每天 00:00–07:59 查的是昨天）·
  导出继承屏上条件且补齐 actor/srcIp/关键词三维（检索与导出现共用 `auditWhere`）。
- 其余：建号撞账号回 409 而不是英文 500 · ComingSoon 的出口按钮指向不存在的路由 ·
  JIT 截断提示指向两条都不存在的补救手段 · 门户用户不再进管理台外壳 ·
  首登强制改密页写「至少 8 位」而后端要 10 位（**默认部署的第一个动作**踩的就是这条）。

### E. 第二批（原「留在台面上的」9 条，已全部落地）

**12. 身份源选项卡真过滤（FR-USER-01）— S ✅**
  选项卡此前只写了一个 `dir` 变量、没有任何消费方：卡上写着「总部 AD 域 3」，
  点进去却是全量表，顶部四个聚合数也永远是全库口径。
  `DirUser` 补 `SourceID`（子查询取绑定表**最早**那条——用 JOIN 会把一个在多源里
  都有绑定的账号复制成多行，目录里凭空多出同名账号），判据与选项卡上的计数**同源**。
  旧后端不下发 → 不过滤（宁可多显示，也不让升级那一刻每个选项卡都变成空表）。

**13. 账号可改（FR-USER-02）— S ✅**
  全仓没有 `PUT /users/{id}`：建号时姓名打错就改不了，而重建又撞上第 14 条（删不掉），
  于是每错一次永久多一行僵尸账号。新增端点只收 name/email；
  **account 显式拒改**并说清原因（它是令牌主体，也是 JIT / 封禁 / posture / 组成员 /
  认证源绑定的关联键，改它会让这些关系整段挂空且不报错）。
  回执经 `enrichDirUsers` 与列表**同形**——不然 PUT 回的是库里那份冻结值，
  页面回填后会出现「刚改完这个人突然又在线了」。

**14. 账号可删 + 影响面回执（FR-USER-15）— M ✅**
  `license.go` 的 409 文案、闲置治理弹窗的说明，两处都把管理员指向「删除闲置账号
  释放席位」，而**那条路根本不存在**。新增 `DELETE /users/{id}`：防自锁（最后一名
  可登录超管）· `guardAdminTarget` · 账号维度连带清理（绑定/组成员/passkey/TOTP/
  授信终端+posture/会话）。**刻意不动** `resources.allow_users` 与 `jit_grants`——
  前者是安全授权（删账号顺手改别的资源的授权面属于越权，且清掉之后再也看不出
  这个资源原来授权过谁），后者保留是为了审计可追溯。两者都写进影响面回执，
  由人去决定怎么清；另有 `GET /users/{id}/delete-preview` 让人**在点之前**就看见。

**15. 自定义管理员角色可改（FR-ADMIN-04）— S ✅**
  后端 `SaveAdminRole` 一直是 upsert（handler 注释也写着「新建/修改」），控制台
  只用了它的一半；而角色有成员时删不掉，于是「收缩某个角色的权限」在控制台上
  无路可走。补「编辑」入口（key 置灰——`users.admin_role` 按值引用）。
  同批给**新建**加一道撞 key 守卫：那个端点是 upsert，直接提交会把现有角色的权限
  静默改掉并**立即**对其下的人生效（requirePerm 现算角色，不看令牌），
  而页面上看起来只是"新建了一个角色"。

**16. 外部目录账号不得提升为管理员（FR-ADMIN-01/03/16）— S ✅**
  提权入口对任何已存在账号一律放行、不看口令来源，于是填一个 AD/OIDC 账号名
  拿到 200 +「已落库」，那个人出现在管理员表里、角色状态一应俱全，
  **但他在管理台登录页永远登不进去**（外部账号 pass_hash 恒空，而管理台登录没有
  认证域路由）。更坏的是这条路径**计入防爆破**：他多试几次就把自己锁掉，
  同 NAT 出口的同事跟着被 IP 维度锁——与「认证源故障不能回『密码错误』也不计入
  锁定」是同一条纪律，只是漏在管理台这一侧。
  选**收敛**（与 FR-ADMIN-16「默认本地密码认证」一致）而不是打通认证域路由：
  两条提权路径（新建管理员的 found 分支 / 改派角色）共用同一道闸，
  拒绝时说清补救路径（先给他重置一个本地口令）。

**17. 审计外送投递失败有了主动信号（FR-AUDIT-14/15）— M ✅**
  失败路径此前只有一行 `slog.Warn` 与系统页里那一格，13 条告警规则、`/diag` 里
  都没有它——合规链路可以**静默断掉**：审计照常落本地库、页面一切正常，
  而 SIEM 那边从某一刻起再也没收到过东西。新增第 14 条规则 `audit_forward_fail`
  （信号取 `audit_forward_targets` 的 last_status/last_ok_at 与现算积压），
  判据是「多久没**成功**过」而不是「上一次失败了」（瞬时失败会被退避重试救回来，
  报它只是噪声）；队列积压单独报一条——那是**不可逆**的（到顶就开始丢新记录）。
  同批加 `/diag` 的 `audit-forward` 项。
  ★顺带修掉一个**播种的坑**：规则播种靠一个全局一次性标记，标记一旦落下，
  后来新增的种类就再也不会被播种——升级后那一类在告警页上根本不存在、永远不会
  触发，而页面上看不出缺了什么（「补列迁移必须配回填」的规则表版本）。
  改成按种类幂等；管理员**删掉**的种类记进 `alert.rules.removed.v1`，不会被复活。

**18. 升级包签名工具（FR-UPG-04）— M ✅**
  验签是 fail-closed 的（没配公钥直接拒，方向正确），但全仓**没有任何签名工具**，
  `BAIDI_UPGRADE_PUBKEY` 也没进任何部署模板——升级包校验在任何真实部署上
  **恒为「校验不通过」**。新增 `cmd/baidi-upgrade`（`-genkey` / `-manifest`（自动算
  SHA-256）/ `-sign` / `-verify`），与 `baidi-license` 同一条分界：私钥留在发布方，
  控制面只配公钥。签的是**文件原文字节**（重新序列化会让签名对不上，而症状是
  「签得好好的包，导入时说签名无效」）。同批把公钥写进 `config.env.example` /
  `deploy.sh` / `install-remote.sh`，并让升级页在未配置时**预先**置灰校验入口
  并说清怎么配，而不是让人先撞一次墙。
  端到端用例真的去跑那个二进制、再用**控制面这一侧**的实现验签——
  工具自己签自己验永远是对的。

**19. 主机侧定期自动备份（NFR-AVL-04）— M ✅**
  `upgrade.CreateBackup` 全仓只有两个非测试调用方：管理员手点导出（产物直接
  stream 给浏览器，服务器上一个字节都不落）与备机来拉时现造。单机部署
  （参考形态、也是演示站的形态）因此**一份自动备份都没有**。
  新增 `StartAutoBackupLoop`（`BAIDI_BACKUP_DIR` + `BAIDI_BACKUP_PASSPHRASE` +
  `BAIDI_BACKUP_INTERVAL` + `BAIDI_BACKUP_KEEP`），**原样复用** backupSources +
  CreateBackup（绝不另造格式）；临时文件 + rename 原子切换（直接写目标名的话，
  进程被杀会留下一个与完整备份同名、有大小、时间也新的半截文件）；备份 0600；
  清理按**文件名**排序而不是 mtime（mtime 会被 rsync/冷备复制改写）。
  未配置时**明说未启用**且 `/diag` 判 **warn 而不是 skip**——与 checkNAT 刻意相反：
  那是"没用这个功能"，而"没有任何自动备份"是每套部署都该关心的事。

**20. 用户状态页的批量解锁与检索（FR-MON-18 P0 / FR-MON-15）— S ✅**
  一次内网扫描或一台 NAT 出口后面的误锁会一次性产生几十条 IP 锁，而此前只能
  一条一条点；受关注用户在真实规模下没有检索手段，只能靠肉眼找——
  而这一页的定位就是「就近处置」。批量解锁**逐条回报**（部分失败不该让整批
  悄悄算成功），检索的过滤字段与占位文案逐字对应。
